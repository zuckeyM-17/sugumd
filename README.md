# sugumd

**すぐ書けて、すぐ整って、すぐコピーできる。** ブラウザだけで動く Markdown エディターです。

Markdown を打つとその場で見出しや表に整形され、右側の目次で全体を見渡せます。書いたものは「全体をコピー」で Notion などにそのまま貼れます。サーバー不要で、GitHub Pages で公開しています。

🔗 https://zuckeym-17.github.io/sugumd/

## できること

- 複数ドキュメントの作成・一覧・切り替え・削除（フォルダなし、更新が新しい順）
- 入力と同時に整形（`# ` 見出し、`- ` 箇条書き、`1. ` 番号付き、`- [ ] ` / `[] ` ToDo、`> ` 引用、```` ``` ```` コード）
- UI は英語（スラッシュコマンドは「表」「見出し」など日本語でも検索できる）
- 右側に見出しの目次。クリックでその見出しへ移動、スクロール位置に合わせて現在地を強調
- 表
  - `/` → 「テーブル」でマス目から行数 × 列数を選んで挿入（数値入力なら最大 50 行 × 20 列）
  - `/3x4` と打てば 3 行 × 4 列をすぐ挿入（1 行目は見出し行）
  - 表にマウスを乗せると下端・右端に「+」が出て、行・列を末尾に追加
  - 表の中にカーソルがあると右上に「表 ▾」が出て、途中への行・列の追加と削除
  - 最終セルで Tab を押すと行が増える
- ブロック
  - コード: 言語ごとに色分け。左上で言語を切り替え
  - Mermaid: ` ```mermaid ` のコードブロックの下に図をプレビュー（`/図` でも挿入）
  - トグル: `/トグル` で折りたたみ。Markdown では `<details><summary>` として保存
  - コールアウト: `/callout` で GitHub と同じ `> [!NOTE]` 形式の色付きの箱（NOTE / TIP / IMPORTANT / WARNING / CAUTION）
- 文字を選んで URL を貼ると、その文字がリンクになる
- 検索
  - 左の検索欄: タイトルと本文から絞り込み、本文の一致箇所を抜粋表示（空白区切りで AND）
  - `Ctrl/Cmd + K`: ドキュメントを探して移動。見つからなければその名前で新規作成
  - `Ctrl/Cmd + F`: ドキュメント内を検索。`Ctrl + H`（Mac は `Cmd + Option + F`）で置換
- 目次の見出しにマウスを乗せて「コピー」（または右クリック）で、その節だけをコピー
- ToDo 一覧: 左の「☑ ToDo 一覧」で、全ドキュメントの未完了の `- [ ]` をまとめて表示。チェックすると元のドキュメントにも反映され、項目をクリックするとその場所へ移動する
- Slack 向けコピー: 「…」→「Slack 向けにコピー」で、Slack の書式（`*太字*`、`<URL|文字>`、`•`、`☐`）に変換してコピー。表はコードブロックになる
- 表示テーマ: 「…」メニューから「システムに合わせる / ライト / ダーク」
- 「全体をコピー」: Markdown と HTML の両方をクリップボードに載せる（Notion などに貼ると見出し・表が再現される）。「…」→「Markdown テキストだけコピー」もあり
- 上部の「Rich / Markdown」トグル（`Ctrl/Cmd + Shift + M`）で、生の Markdown を直接編集
- Markdown のテキストを貼り付けると整形して取り込む
- 保存: ブラウザの localStorage に自動保存（0.5 秒後）。`navigator.storage.persist()` で自動削除されにくくしている
- PC のフォルダにも保存（Chrome / Edge）: 「…」→「PC のフォルダにも保存する…」でフォルダを選ぶと、1 ドキュメント = 1 つの `.md` ファイル（ファイル名はタイトル）として書き出し続ける
  - Dropbox / Google Drive / iCloud などの同期フォルダを選べば、自動でクラウドにもバックアップされる
  - 接続時・再接続時に、フォルダとブラウザの内容を新しい方に合わせる。フォルダにある他の `.md` も取り込む
  - ブラウザのデータが消えても、同じフォルダを選び直せば元に戻る
  - ファイルとドキュメントの対応は、フォルダ内の `.sugumd.json` に記録する
  - ブラウザを開き直したときは、上部の「📁 フォルダに再接続」を押してアクセスを許可する（Chrome の仕様）
- バックアップ: 「…」メニューから全ドキュメントを JSON で書き出し／復元（同じドキュメントは新しい方を残す）、1 件ずつ `.md` で保存

## スマホ・ホーム画面アプリ（PWA）

- iPhone は Safari の共有ボタン →「ホーム画面に追加」で、アイコン付きの全画面アプリとして使える（Android は Chrome の「アプリをインストール」）
- 一度開けば、オフラインでも起動・編集できる（Service Worker がアプリ本体を保存する。Mermaid は一度使うと保存される）
- 新しい版を公開すると、次に起動したときに切り替わる
- 注意: ホーム画面から開いたアプリと Safari で開いたページは、データを共有しない。移すときは「Export backup」→「Restore from backup」
- 注意: iOS では「Also save to a folder」は使えない（ブラウザが未対応）
- 狭い画面では、ドキュメント一覧（☰）と目次（☷）が引き出し式になる。タッチ端末では表の「+」はセルをタップすると出る

アイコンの元は `public/icons/icon.svg`。PNG（180 / 192 / 512 / マスカブル 512）はこの SVG から書き出している。

## 開発

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # ユニットテスト（Vitest + jsdom）
npm run build   # dist/ に静的ファイルを出力
```

## GitHub Pages への公開

1. このディレクトリを GitHub リポジトリとして push（ブランチは `main`）
2. リポジトリの Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
3. `main` に push すると `.github/workflows/deploy.yml` がテスト → ビルド → 公開する

`vite.config.js` の `base: './'` により、`https://<user>.github.io/<repo>/` のようなサブパスでもそのまま動きます。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/store.js` | ドキュメントの保存・読み込み・バックアップ（純粋関数） |
| `src/folder-sync.js` | フォルダ同期で何を読み書きするかを決める（純粋関数） |
| `src/folder-store.js` | File System Access API / IndexedDB の薄いアダプター |
| `src/folder-controller.js` | フォルダ保存の状態管理と書き込みの順序制御 |
| `src/editor.js` | Tiptap エディターの組み立て、Markdown 貼り付け |
| `src/slash-command.js` | `/` コマンドメニュー |
| `src/table-picker.js` | 表のサイズを選ぶマス目 |
| `src/table-controls.js` | 表の「+」バーと「表 ▾」メニュー |
| `src/markdown-utils.js` | 目次の抽出、表サイズの解釈、Markdown 判定 |
| `src/main.js` | 画面の組み立てとイベント |

## 制約

- フォルダ保存を使わない場合、データは「そのブラウザのそのサイト」にだけ保存される。ブラウザのデータ削除で消えるので、定期的にバックアップを書き出すこと
- フォルダ保存は Chrome / Edge などの Chromium 系ブラウザのみ（Safari / Firefox は API 未対応）
- アプリを開いている間に、外部のエディターでフォルダ内のファイルを書き換えても即時には反映されない（次の接続・再読み込み時に、新しい方が採用される）
- 同じアプリを複数タブで開いてフォルダ保存すると、対応表の書き込みが競合することがある
- 画像、脚注、表のセル結合など、この編集画面に機能がない Markdown 記法は、編集すると失われる
- 表の中に表は作れない（Markdown で表せないため）
